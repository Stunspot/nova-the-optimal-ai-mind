# A corrected pursuit with a stale native goal

This is a fictional worked decision, not a receipt for a real host operation.

The user pauses an estate repair at a safe breakpoint. The project owner stores that pause and the remaining work. A previously scheduled wake arrives later: the agent reads the current project state, sees the pause, and performs no repair. It does not treat the old live goal text as continuing authority. If permitted, the scheduler is paused through its own tool and its response inspected; an unsuccessful scheduler change is reported as such.

The user later says: resume, and make every authored capability mandatory; the high-payoff ones only determine order. The exposed native goal tool cannot edit the objective or resume its displayed paused status. The agent keeps the correction in the existing project record, confirms the write, and continues the authorized work from the retained breakpoint. The native goal is accurately described as stale; no claim is made that its status changed. The actual host's budget or terminal-control rules still apply.

The agent does not complete an unfinished goal to get a new slot, start a second project ledger, ask for the same permission again, or reduce the scope to the prioritized products. A later task follows the real project retrieval cue and current user direction. If automatic continuation is needed, it separately verifies the explicitly authorized scheduler's current state. A manual cue alone would support only manual resumption.
