# Vacancy to truthful application

Use the smallest useful scope. For one answer, inspect its question and supporting facts and draft that answer. For a complete application, first save the actual posting and candidate history in a private case. Keep employer facts separate from applicant facts and a fictional sample separate from real experience.

Translate the posting into a few material required, preferred, responsibility and administrative criteria. Separate a hard license/location/schedule condition from desirable experience. Unknown eligibility is a question to resolve; preferred experience may be a candid gap. Record an adjacent skill as an explanation of transferable method, not a synonym that makes the applicant appear experienced with a tool they have never used.

Map each material candidate fact to an accountable source and an exact proposed fragment in its selected document. This includes employer/title/date and education facts, not only achievements. Use the same EVD identifier across criteria only while its source and strength are unchanged. Preserve conflicting source records; source currency does not mean authenticity.

Build an internal selection thesis: why this applicant could plausibly do this work, using two or three credible examples. Use that thesis to choose order and emphasis. Prefer relevance and evidence over prestige. Conventional headings, meaningful text and straightforward chronology are useful defaults, not an ATS guarantee. Respect a contrary explicit format instruction. Never hide a gap through false dates or upgrade supervised exposure into independent proficiency.

A letter identifies this role, shows a relevant example and a second useful connection, then closes simply. An application answer answers the actual question; select situation/action/result detail only where it helps. Keep evidence IDs, privacy notes and uncertainty analysis out of candidate-facing prose. Native exact-fragment checks are only one mechanical aid; inspect all factual prose for unsupported additions and misleading omissions.

For a work sample, prefer existing shareable work, then a sanitized derivative with established permission, then a bounded simulation. Say what the sample proves, its inputs and limitations, and any required AI-assistance disclosure. The product does not undertake unpaid employer work or obtain permission on the applicant’s behalf.

On return, read the current case, sources, named gaps and prior reviews. Compare the changed posting/date/answer with the prior evidence and repair only affected claims and constraints. Review the current snapshot after correction. Keep both source versions when they explain a conflict; do not overwrite the evidence with the desired answer.
