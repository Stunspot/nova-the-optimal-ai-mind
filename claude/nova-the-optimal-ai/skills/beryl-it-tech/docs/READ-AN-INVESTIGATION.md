# Read the evidence and the next useful move

Open **Investigations** and choose an entry from **Investigation**. Personal entries are labelled **Your material**; the three supplied examples are labelled **Fictional**. The examples demonstrate reasoning and boundaries without claiming work on a real device.

## Begin with the problem and unresolved decision

Read the reported symptom, device, desired outcome and current disposition. **Next useful move** gives the prepared action, the question it is intended to advance, its next actor and any required authority. A named stop or referral takes precedence over casually trying another test.

Under **Evidence across the failure path**, inspect what the prepared record calls reported, observed or measured. Those labels state the record's evidence basis; importing them does not authenticate a measurement. **Other observations** keeps evidence visible when no layer mapping was supplied.

Choose a **Rival explanations** entry to read its supporting and contradictory evidence together. **Discriminating tests** shows linked tests, predicted distinctions and recorded results when provided. Missing evidence or a missing prediction stays missing. The companion does not infer that an unlinked explanation is supported or that an absent contradiction cannot exist.

Command text is readable evidence and proposed work. The companion provides no control to run it.

## Follow the original and return

Choose **Read exact source**, or a filename under **History, sources and review**, to inspect the retained material. Use **Close** or Escape to return to the investigation. The original remains available through **Save a copy of the exact original**.

A source may be used by a current investigation, retained only with an earlier revision, or still awaiting interpretation. Read that status with the passage. Retaining a file does not mean Beryl has examined it or drawn a conclusion from it.

## Tell current work from history

Choose **Refresh prepared work** after Beryl publishes locally. The displayed revision stays selected. If newer work exists, an earlier-revision notice offers **Read latest revision**. Use **Received revision** to return to a particular preserved version.

Each revision keeps its own native record, source links and supplied review. **Review of this exact revision** names the stated author and whether the review is independent, a self-check or imported. It binds the supplied review to that record; it does not authenticate the author or independence. A later revision does not automatically inherit an old review.

**All recorded tests and results** and **Original failure conditions, changes and verification** expose the history needed to judge a closure claim. The original problem still needs verification under its relevant conditions.

## Continue in Beryl's conversation

Choose **Copy exact request for Beryl**. Paste the request into your existing conversation, add the new fact or question, and ask Beryl to inspect the latest saved state before publishing a revision. The copied request identifies the displayed investigation and its original fingerprint. Beryl maintains the native case and the local publication; you do not need to transcribe records.

IT Work Reviewer remains a separate review practice. Ask for that review when its independent challenge is needed, preserving what it actually examined and which revision it applies to.

[Return and recovery](RETURN-AND-RECOVERY.md) explains how to close, reconnect and preserve the whole saved folder.
