# Build documents for reading, revision, and page reality

An editable document earns its value through a stable reading structure, not decorative formatting pasted over loose prose. Shape the argument before styling it, then use the document's real structural features to carry that shape.

## Let the reading task choose the form

Use prose for explanation, a lead callout for a decision, numbered steps for sequence, bullets for non-sequential factors, a checklist for actions, and a table for truly repeated comparable records. When cells become miniature essays, return that material to prose, bullets, or an appendix. Form should reduce reader effort.

## Build a real hierarchy

Establish a title, heading ladder, body style, list style, table treatment, page furniture, and source treatment appropriate to the document's use. Use semantic headings and real lists so navigation, reflow, conversion, and assistive reading retain the document's logic. Make decorative choices serve hierarchy: restrained color, spacing, type contrast, and white space can carry more professionalism than crowded ornament.

For a supplied template, treat the template as the visual authority. Work in a copy, preserve its meaningful styles and structure, and record any intentional deviation. For a fresh document, choose one coherent visual system rather than assembling a small museum of unrelated defaults.

## Design tables as information surfaces

Give every table a clear reader question. Define column widths from the content, reserve space for long fields, keep short status/date/amount fields compact, and allow rows to grow around wrapped text. Use clear headers, meaningful alignment, visible but restrained borders, and breathing room within cells. Inspect tables on the actual page: a syntactically valid table can still pinch, spill, or become unreadable.

## Review the editable source and its page form

Check, to the available degree:

- title and headings communicate the document's hierarchy;
- paragraph rhythm supports scanning without fragmenting thought;
- lists, tables, links, citations, captions, and headers remain functional;
- page breaks, widows, cramped tables, clipped text, repeated headers, and page furniture read cleanly;
- images carry useful descriptions or are explicitly decorative;
- metadata, tracked material, comments, hidden text, and revision residue match the approved privacy state.

Rendered page inspection is the visual gate where the host supports it. When that surface is unavailable, run the available structural checks, mark visual QA unperformed, and leave the document editable for that later pass.

## Hand off a document honestly

Name the editable source and any PDF derivative. Say whether layout was rendered or structurally checked, whether template fidelity was reviewed, and which remaining reader, approver, or native-app step owns final acceptance. A document is ready for its stated use, not universally proven by its extension.
