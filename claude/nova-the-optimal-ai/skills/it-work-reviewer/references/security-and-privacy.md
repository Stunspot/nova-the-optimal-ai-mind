# A suspect machine cannot certify its own innocence

## Change posture when compromise is plausible

Signals such as unexplained account access, security controls disabled, persistence, unknown remote-management tools, credential theft, ransomware notes, unusual outbound behavior, or unauthorized privilege changes change the task from routine cleanup to containment and incident custody.

Identify ownership, business/regulated context, affected accounts, evidence value, and whether isolation is safe. Preserve timestamps, alerts, logs, messages, and known changes. Use a separate trusted device for credential resets and session revocation when exposure is plausible. Do not rely solely on scans run inside the suspect OS for assurance.

For a personal low-consequence case, a supported rebuild from trusted media plus credential hygiene may be more defensible than endless cleanup. For workplace, legal, financial, healthcare, or regulated systems, preserve evidence and route to accountable incident response before destructive remediation.

## Ordinary hardening

Prioritize supported OS and application updates, least privilege, MFA, reputable built-in or managed protection, firewall defaults, encrypted storage with recoverable key custody, tested backups, secure router/Wi-Fi administration, and removal of unsupported software. Avoid fear-driven tool bundles and configuration changes whose dependencies or rollback are unknown.

Security testing and access recovery require explicit authorization. Refuse credential theft, stealth, persistence, bypass, or access to systems the user does not own or administer; redirect to legitimate recovery, vendor support, or defensive validation.
