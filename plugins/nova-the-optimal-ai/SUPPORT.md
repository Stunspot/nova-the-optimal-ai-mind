# Support

Use the [troubleshooting guide](docs/TROUBLESHOOTING.md) first. If the problem remains, open a bounded issue in [Stunspot/nova-the-optimal-ai-mind](https://github.com/Stunspot/nova-the-optimal-ai-mind/issues) for a package defect, installation failure, documentation barrier, or focused proposal.

Include the actual installed Free product version, host and operating system, installation source, exact command or request, complete sanitized error, expected result, smallest safe reproduction, and the state that failed: package presence, host discovery, enabled state, restart state, invocation, optional estate configuration, tool availability, or behavior.

Remove credentials, private prompts, personal data, customer material, sensitive paths, databases, and raw receipts. Use [Security](SECURITY.md) instead of a public issue for vulnerabilities or privacy exposure.

This free source candidate provides no hosted Nova service, service-level agreement, response-time guarantee, account entitlement, or promise of custom implementation.

## Worldline 2 recovery

A missing or unavailable timeline does not establish lost conversations: check the configured estate, exact user/agent scope, dates and retained coverage. Reading never initializes an empty replacement. Off or unconfigured capture does not block earlier retained events. New occurrence fields require Cognitive Continuity 0.3.0 or newer. Turn ordinary capture off to roll back behavior; retain a compatible runtime for the evolved store. Preserve existing snapshots and handle any history restore as separate governed recovery.

## Update, return and rollback

Use the [Free4 upgrade procedure](docs/UPGRADE.md) to apply a selected complete edition through the live host, verify the intended installed version and preserve owner data. An extracted folder is staging, not proof of update. Keep the prior package for rollback.

For a missing earlier result, inspect the original artifact or selected owner store before creating anything. A different empty catalog or estate is not evidence of data loss. For scope or root conflicts, use [the troubleshooting guide](docs/TROUBLESHOOTING.md#scope-or-root-conflict); do not globally rewrite selectors or initialize a replacement store to dismiss a read error.
