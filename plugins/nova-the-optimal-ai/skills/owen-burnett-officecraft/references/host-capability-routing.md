# Route through observed capability, not assumed brand magic

Officecraft orchestrates the capabilities actually available in this run. A named host surface earns a route only when it is installed or connected, applicable to the requested artifact, and capable of preserving the relevant properties of the job.

## Observe before promising

For a requested surface, establish the available creation/editing route, render or inspection route, relevant template/native semantics, file or connector destination, and any required authority. Separate these states:

- **Available:** package or tool can be selected in this host.
- **Applicable:** it fits the requested artifact and constraints.
- **Executed:** it was used on this job.
- **Inspected:** the stated check ran on the resulting artifact.
- **Native-verified:** the connected native surface confirmed the relevant result.

Do not promote an earlier state into a later claim.

## Select the narrowest capable route

| Need | Route preference | Fallback result |
|---|---|---|
| New editable office file | Active artifact-production capability with a real output path | Complete source-ready production packet |
| Existing native cloud artifact or template | Connected native surface with a confirmed target/copy | Preserve source and specify a safe adaptation plan |
| Visual quality | Renderer, export, or opened native view | Structural review plus explicit unperformed visual check |
| Workbook recalculation or live controls | Active compatible workbook surface | Formula and data-lineage audit marked pending native calculation |
| Branded presentation | Authorized template or connected design surface | Slide map and visual specification pending native build |

Choose a substitute for preserved properties, not name resemblance. A generic file export may create an artifact yet lose native controls, template behavior, or editability; record that tradeoff before treating it as equivalent.

## Keep volatile facts at the adapter layer

Adapter files carry host-specific selection and recovery cues. Keep operating doctrine stable: it should ask for an observed route and describe the evidence boundary, rather than memorizing private tool names or assuming a vendor's current behavior. Refresh adapters when host capability evidence changes.

## Recover from a missing route

First test the simplest route that could restore the normal path. If it remains unavailable, continue independent work: settle the brief, spine, source custody, artifact specification, and QA plan. Label the exact assurance lost and the event that restores it. A temporary capability loss changes the status of the result; it does not erase the work already prepared.
