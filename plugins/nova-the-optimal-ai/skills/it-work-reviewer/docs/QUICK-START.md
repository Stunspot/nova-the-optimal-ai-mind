# Review one decision

Invoke `$it-work-reviewer` with the case/plan, the decision it is meant to support and its revision or update time. Say whether you need plan review, work-claim review or repair-closure review. Include the actual evidence and authority limits; do not substitute the author's explanation for missing records.

The reviewer returns a scoped verdict, concrete findings, closure conditions and residual boundary. A clean bounded plan can pass without future physical execution. An unsupported repair claim cannot. A review does not authorize access, spending or destructive work. If the same assistant wrote the artifact in the same context, label its pass a self-check, not independent execution.

Use the separately installed Beryl operator Studio's IT review view only to display a supplied review beside a case. This reviewer skill has no local workspace. Explicit JSON case/revision mismatches are shown there, while free-text binding remains unknown. Retain the original review separately and re-review affected claims after material case changes.
