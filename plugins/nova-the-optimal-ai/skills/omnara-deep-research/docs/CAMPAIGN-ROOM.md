# Your campaign room

Extract the complete package into a stable folder. Install Python 3.10 or newer if it is not already available. Double-click **Open.cmd** on Windows. On macOS, run `python3 workspace/open.py` from the extracted folder; `Open.command` provides the same entrypoint after granting it executable permission (`chmod +x Open.command`). The launcher waits for the matching local service before opening your browser. It works after reboot without an always-running service.

Your native vaults live in `Documents/OMNARA Campaigns`, outside the application. To use another owner-selected folder, launch `python workspace/open.py --data-root "your folder"`, or set `OMNARA_HOME`. Keep a stable data folder when updating the application. Open resolves its own package location and matches both this application copy and the data home. A busy port leads to a free loopback port. Repeated Open reconnects the matching instance. Do not bookmark a port as the permanent Open action.

Find a campaign by title or inquiry in the persistent campaign index. The **Research cockpit** opens on the verbatim question, native coverage frontier, next pass and blockers, reading queue, linked claims and contradiction text. These are projections of your actual vault; source state counts are ledger counts, not a progress score. Select a source or a claim's source reference to open **Reading queue & notes**, where the searchable queue stays beside a readable evidence note. Use **Edit note** to change the exact native Markdown and **Read note** to return to its safe text projection. Source details expand for title, locator and earned-state edits. The reading view compacts campaign context; expand **Campaign inquiry** whenever you need the full question.

Create a campaign with a title and the question exactly as asked. **Inquiry & scope editor** maintains framing, hypotheses, coverage loci and resume point. Record sources, earned states and evidence notes; add provisional claims and their source IDs; maintain the coverage matrix and contradictions; compose a report outline and ordered Markdown section drafts. **Native files** exposes the native text when a specialised field is not provided. The research agent sees the exact same files, not an interface-only copy.

Use **Save vault** to commit. Source counts are recomputed from retained native ledger rows. The existing native validator refuses broken links, unknown states, unearned reading states, missing substantive evidence notes, and unsupported complete-campaign declarations. A conflicting agent or second-window edit yields a reload instruction instead of silent overwrite. Prior native file contents are preserved under the data home's `.workspace/history` folder for recovery. This is recoverable local editing, not a distributed transaction across external programs; avoid saving simultaneously with an agent actively writing the same vault.

**Import native vault** asks for the full path to one existing campaign folder. It validates and copies that vault into your data home without modifying the original. Import refuses linked files and folders. Large corpora should retain their canonical source stores and place source pointers in the campaign. **Export vault** downloads the complete campaign as a ZIP. **Next-pass handoff** downloads a Markdown prompt naming the real vault, question, current coverage, blockers and next unverified edge. Give that prompt to your research agent. Export reflects saved records; save current edits first.

Two working skins are included. **Evidence Bench** uses dark mineral/slate instrument housings and amber routing, with compact native evidence registers. **Field Folio** is an ivory scholarly dossier with spacious reading leaves and next-pass/claim references in its margin. Both include the cockpit, source-note reader, editors, dialogs and narrow layouts. The skin preference is browser-only presentation state. Changing it does not change evidence.

## Read, change and hand off a campaign

Start with an open campaign and its native files loaded. If the index has no records, use **Create a campaign** or **Import native vault** first.

1. Select **Research cockpit**. Review the verbatim inquiry, coverage frontier, recorded blockers and next pass. The reading queue lists sources without the recorded `deeply-read` state; an empty queue does not certify completion.
2. Select a source in the queue or a claim's source-reference button. **Reading queue & notes** opens that source with its note beside the searchable source list. Expand **Campaign inquiry** to recover the full question without leaving the note.
3. Select **Edit note**, change the native Markdown, then select **Read note** to inspect its safe text projection. The projection retains unknown markup as text; it does not execute HTML. Source title, locator and earned states are available under **Edit source title, locator & earned states**.
4. Select **Save vault**. The status confirms that the native vault was saved and prior files retained. If validation refuses the save, correct the named prerequisite or evidence gap; the draft remains available in the open page. If a conflict reports an agent or another-window change, preserve your draft text separately before **Reload**; reapply only changes still needed.
5. Select **Next-pass handoff ↓**. A Markdown download names the saved campaign, inquiry, resume point, active coverage and blockers. Unsaved edits prevent export: save them first. Give the handoff to your research agent, who works on the same native files.

You can stop safely after **Save vault** confirms success. Reopen through **Open.cmd** or the supported platform entrypoint and select the campaign in the index. Back up the separate campaign data folder for recovery.

The room starts empty. Demonstration screenshots are explicitly labelled EXAMPLE and do not seed customer research. Research quality, authority, source truth, and semantic citation support still require judgment. The existing campaign helpers continue to validate, audit and assemble the same vaults.

Desktop shortcuts are optional. Ask your assistant to create one only if you want one, and confirm the chosen location. Nothing installs host icons automatically.

The service binds only to `127.0.0.1`, has no cloud dependency, and makes no outbound research calls. Open supplies a fresh private instance token in the browser fragment; do not share that launch URL. Foreign browser origins and unrelated Host headers are refused. Close the browser whenever you like; the local service can remain until logout/reboot. To diagnose a failed start, run `python workspace/open.py --serve --data-root "your folder"` in a terminal and retain its error. Updates and uninstall leave the separate native data home intact. Back up that folder as ordinary research data.
