# Coordinate the live organization, not an imagined API

Collaboration primitives are host contracts. Inspect current injected tools before relying on names, arguments, model routes, context forks, concurrency, nested delegation, message timing, waits, interruption, or cancellation.

## Map the current control surface

At the 2026-08-31 evidence cutoff, the app contract exposed distinct primitives for spawning an agent, messaging a live or idle agent, triggering a follow-up turn, interrupting current work, listing live agents, and waiting for mailbox updates. This is task-envelope evidence, not timeless syntax. Read `source-and-currentness-register.md` and prefer the live schema.

Preserve the canonical identifier returned by creation. Treat dispatch as work admission, never completion or commit.

## Match control action to intent

- **Message:** deliver a correction, evidence pointer, scope, relation, exposure, authority change, or return request.
- **Follow-up:** start another bounded turn after a member is idle or finished.
- **Interrupt:** stop current sampling for cancellation, authority revocation, material misdirection, contamination, or changed scope. It proves neither rollback nor unchanged state.
- **List:** inspect topology and status when a decision depends on it.
- **Wait:** yield until a mailbox event or user steering arrives, only when useful root work is exhausted or a dependency truly blocks progress.

Do not replace event-driven waiting with repeated listing. Do not ask generic status questions when the host already exposes status.

## Let user steering outrank the organization

A new user message may add, correct, narrow, replace, pause, or cancel the mission. The root classifies the delta first. Continue unaffected contributions; redirect compliant work in place; interrupt work whose objective or authority disappeared. Reconcile uncertain filesystem or external state before retrying.

Do not reconstruct an equivalent team merely to make the new diagram neat. After redirect or interruption, mark prior write and commit state unknown until authoritative readback.

## Keep dependencies and interaction rounds visible

Do not dispatch downstream work before its accepted inputs exist. Inspect the prior return and authoritative state before triggering the dependent slice. A worker's complete status establishes only that its turn ended.

A cross-response round begins only when its exposed return exists and a named transformation can change the result. Keep its input IDs, exposed fields, budget, consumer, and exit condition visible. A second round needs new evidence, discriminating disagreement, failed check, or unresolved criterion—not merely momentum.

## Reconfigure through observed events

Recruit, release, replace, split, merge, reroute, change exposure, change resolver, or change regime when a named observation warrants it. Use `assets/organization-transition.template.md` when the change affects responsibility, state, authority, or phase.

Before the new phase starts, disposition current responsibilities, reconcile mutable state, classify task/progress/evidence/scratch/artifact state, confirm authority and sources, then compile the next ready frontier. The transition record does not prove that actions completed; live state and evidence do.

## Control nested teams

Root-owned spawning is the default. Nested delegation is justified when the host allows it, the parent owns a bounded subproject and child merge, child tasks are independently ready, depth and budget are capped, and the root can still observe authority, conflicts, state, and closure. A recursion-shaped org chart is not sophistication; occasionally it is just latency in a nice hat.

## Close with explicit dispositions

Before final synthesis, account for every member as working, returned, reconciled, failed, interrupted, cancelled, released, or unavailable. Stop or release work that no longer owns responsibility. Preserve pending state only when a named re-entry condition exists. A temporary organization that survives its mission has mistaken itself for middle management.
