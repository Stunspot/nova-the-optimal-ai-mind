# Nova estate contract

The selector registry format is `nova-path-selectors/v1`. `NOVA_DATA_ROOT` names one customer-controlled absolute root outside `.codex`; the authoritative registry lives at `estate/path-selectors.json` beneath it.

A configured estate has exact active values for `NOVA_DATA_ROOT`, `NOVA_CONTINUITY_HOME`, `DENNIS_PROJECT_HOME`, `DUNBAR_STORE`, `CORKBOARD_HOME`, `NOVA_COMMONPLACE_HOME`, and `NOVA_CONCORDANCE_HOME`. The last two resolve exactly to `memory/commonplace` and `derived/concordance`; they must differ and must not nest. New Nova Free estates record `MIND_CORE_DATABASE` and `MIND_HOOK_RECEIPT_DIRECTORY` as null because the product requires no prompt hook, embeddings, vector database, local model, or Arm's Reach layer. Commonplace semantic retrieval is a separate explicit post-initialization option: it uses a customer-provided loopback Ollama embedding service, stores only derived vectors in Concordance, and does not populate either legacy MIND selector. A healthy older estate may already have non-null legacy values; additive upgrade preserves those exact registry and helper values and never follows, rewrites, deletes, or forwards them into Nova-launched service processes.

The registry is configuration, not a state store. Cognitive Continuity, Dennis Stratton Project Management, Dunbar, Corkboard, and Commonplace own their records. Commonplace holds deliberate general notes and captures; Concordance is disposable lexical-default navigation over that canon, with optional local semantic retrieval and bounded graph traversal. Fixed federation adapters read Dunbar, Corkboard, Dennis, and Continuity through their admitted interfaces without copying or mutating their stores. Authenticated history and as-of reads remain inside Commonplace. Promotion produces non-executable proposals and performs no target-owner write. Giles, Dex, skills, repositories, external corpora, and every other specialist retain their own canon. The Nova Operations `run` command reads the registry stably, rejects paths that escape the root or cross a symbolic-link or reparse edge, removes inherited managed selectors, injects the exact registry snapshot, and starts the selected bundled service without a shell. Global environment variables are not part of Nova Free's correctness path.

The operating-system default estate is discovered directly. A customer-approved nondefault root is remembered by `nova-current-estate-locator/v1` at the platform's per-user configuration location: `Collaborative Dynamics/Nova Operations/current-estate.json` on Windows and macOS, or `$XDG_CONFIG_HOME/collaborative-dynamics/nova/current-estate.json` on Linux. This file is a root pointer only. The selected estate registry must corroborate `NOVA_DATA_ROOT`; a default-root duplicate, malformed pointer, conflicting root, symlink, or reparse edge fails closed.

A new initialization stages the complete estate beside the final root, initializes Cognitive Continuity and an empty generation-zero Commonplace there, builds an empty Concordance bound to that exact workspace, writes the manifest and helper environment text, writes the registry last, and atomically renames the completed stage into place. Any staged service failure removes the stage and any empty parent directories created by that attempt. Publishing a custom root and its discovery pointer is treated as one setup operation; an ordinary locator-publication failure removes the newly published empty estate.

The only existing-root auto-repair is legacy_1_0_0_partial: the exact empty directory skeleton created by the old v1.0.0 initialization order before Continuity failed. It requires no registry, estate manifest, Continuity manifest, or file of any kind. The footprint is inspected before staging and revalidated immediately before replacement. The original empty tree is held for rollback until the completed estate and any custom-root locator are published. Any unknown directory, file, symlink, or reparse edge disables auto-repair and is preserved.

An explicit upgrade permits only known additive selectors. A healthy 1.0.3 registry missing Commonplace and Concordance reports `upgrade_required`, and its plan names only those two additions; a missing unrelated core selector is corruption. Upgrade stages and verifies new owned roots, preserves every existing owner byte, establishes a required custom-root locator only when absent, preserves a valid corroborated locator byte-for-byte, updates the helper and product service metadata, then publishes the registry as the selector commit point. A current `nova-estate-manifest/v1` receives the service update directly. A historical `nova-data-estate/v1` manifest remains immutable evidence and is never relabeled or overwritten; the product publishes `nova-emergent-estate-services/v1` at `estate/nova-emergent-services.json` as an additive transactional sidecar. It does not replace the root or move, merge, initialize over, or delete existing service data. Conflicting selectors, product-service metadata, or current-estate pointers stop before mutation. A registered canonical Commonplace whose directory is missing is a recovery condition and is never replaced with a newly initialized empty store.

`--apply-user-environment` is optional Windows convenience only. Never pass it on macOS or Linux. When explicitly authorized on Windows it copies current registry values to the user's environment; a new process is needed to observe those ambient copies. The registry-backed launcher itself never requires that environment change or a restart.

Status and doctor report Continuity read support and mutation support independently. They also report canonical Commonplace initialization and verification separately from Concordance states such as current, stale, unavailable, or incompatible; a derived-index failure is never reported as canonical data loss. Readable state on a filesystem the canonical Continuity runtime will not mutate is `read_only`, never healthy full operation. Exports, forget plans, and recovery backups remain external artifacts whose destinations must be user-chosen outside `.codex`, the active Continuity source, and every active Nova selector boundary.
