# Preserve striving when the host cannot carry the whole loop

Striving depends on a host for actual persistence, wakeups, tool execution, hard budgets, and enforcement. When an affordance is absent, preserve the user's direction through the strongest truthful continuation instead of simulating machinery that did not run.

## Name the lost guarantee precisely

Without persistent state, current work can advance but later resumption is not guaranteed. Without a real reload route, stored state will not re-enter the work by itself. Without wakeups or background execution, a checkpoint can be prepared but time will not advance the pursuit. Without a required tool, data source, budget control, or authority, independent work may continue while that exact observation or mutation remains unperformed.

Keep requested, attempted, prepared, persisted, reactivatable, and executed state distinct. Do not translate missing host capability into model prose claiming the capability occurred.

## Continue the independent branch

Keep doing the live work that does not depend on the missing edge. Preserve a checkpoint or handoff only when it materially lowers the cost of honest resumption for a real next custodian. Do not respond to one unavailable mechanism by manufacturing plans, test assets, dashboards, authority packets, or other consolation artifacts unrelated to the pursuit.

Use `assets/pursuit-state.template.json` only when another task, model, or harness must resume and no governed goal, project, or continuity store can carry the state. Copy it to the actual handoff location, fill only what is known, write `current_direction` as purposeful natural language, name the lost guarantee, and run `python scripts/validate_pursuit_state.py <handoff.json>`. The shipped template is intentionally incomplete and must not validate unchanged.

A valid portable handoff proves only that its custody claims are internally coherent. It does not prove that a destination received it, that a host will surface it, or that work resumed.

## Choose a truthful disposition

Rest with a re-entry condition when restoration is plausible. Degrade to a narrower result only when it remains useful and the user's authority permits the reduced promise. Transfer to a human or capable harness when authority or infrastructure belongs there. Release the route when the minimum useful promise cannot survive the missing capability.

When capability returns, retrieve the authoritative state and reconcile it with the checkpoint before continuing. Supersede provisional conclusions rather than letting the degraded version circulate beside the restored result. A stale wakeup never outranks a later correction or cancellation.
