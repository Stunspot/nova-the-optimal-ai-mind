# Vacancy-to-application method

## 1. Establish the selection problem

Capture the employer, role, location, schedule, contract type, deadline, application route, required documents, requested questions, and stated selection criteria. Preserve the posting verbatim in the source register. Record its retrieval date when obtained from the web because postings change or disappear.

Classify criteria as required, preferred, responsibility, context, or administrative. Do not turn every noun into a keyword target. Identify the small set of criteria that determine credibility and fit.

## 2. Build the evidence-to-claim matrix

For each material criterion, record its stable ID, exact posting language, importance, evidence ID, one or more existing `SRC-*` source-register IDs, evidence strength, proposed claim, artifact destinations, confirmation status, and unresolved risk. One evidence item may support several criteria when its source and strength binding remain unchanged; do not mint duplicate proof merely to make every row look unique.

A direct match uses evidence of substantially the same competence. An adjacent match explains transferable method or context without pretending equivalence. A gap stays a gap; it may be addressed through honest learning plans or work-sample guidance, not fabrication.

## 3. Choose the application thesis

Form one short internal thesis: why this person can plausibly perform this role. Connect the vacancy's highest-value needs to two or three evidenced strengths. Use the thesis to select and order evidence, not as a slogan repeated in every artifact.

Select evidence by relevance and proof strength, not prestige. Preserve older or unusual experience when it establishes a needed capability. Compress material only when it does not help this vacancy and omission does not create a misleading chronology.

## 4. Draft the resume

Use a parse-safe structure when the employer does not specify otherwise: name and approved contact details, role-matched summary only if useful, grounded skills, reverse-chronological experience, selected projects or work samples, education and credentials.

For bullets, prefer action + method + context + supported result. Use numbers only when supplied or confirmed. If impact is qualitative, state the concrete change without inventing a metric.

Keep the document single-column with standard headings, ordinary fonts, meaningful text rather than images, no headers or footers for essential content, and no tables for chronology. Use long-form plus acronym when both are common and truthful.

## 5. Draft the cover letter

Use a lean structure:

1. identify the role and strongest fit;
2. show one evidenced example tied to a central need;
3. show a second example, transition logic, or work-sample proof;
4. close with interest and availability without assuming an interview.

Do not summarize the whole resume. Do not flatter the employer with unsupported research. Register current employer facts and retrieval dates when they are used.

## 6. Draft application answers

Create a question ledger with question text, limit, required status, answer, evidence IDs, unresolved facts, and user-attestation status. Answer the actual question. Use STAR or SOAR only when an example benefits from that structure. Explain the candidate's own decisions and methods.

For tools and skills, distinguish exposure, supervised use, working proficiency, independent proficiency, and adjacent experience.

## 7. Prepare work-sample guidance

Rank existing shareable artifacts first, then sanitized derivatives with permission, then a bounded new sample using fictional or public data. For each sample, state the competency proved, timebox, inputs, deliverable, evaluation criteria, confidentiality boundary, and AI-assistance disclosure.

## 8. Reconcile and hand off

Recheck every artifact against the evidence matrix and posting instructions. Put unresolved claims in one visible register. The submission checklist must distinguish finished files, user confirmations, user attestations, external actions, and post-submission records.

The final choice to submit and every legal attestation remain with the user.
