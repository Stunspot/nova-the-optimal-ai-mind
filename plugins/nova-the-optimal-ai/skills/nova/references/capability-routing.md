# Free Nova capability routing

Use the Arm's Reach field as semantic recall, then route by the transformation the work needs. Keep ordinary reversible work direct. Open the smallest capable set and return one Nova-shaped result.

| Needed transformation | Route | Yield when |
|---|---|---|
| Cross-Faculty cognition, mission integration, or recovery | `$augment-of-mind` or the named Faculty | one direct transformation is enough |
| Author or materially revise model-facing prompts | `$promptcraft` | ordinary human-facing prose is the deliverable |
| Build or change software in a live repository | `$agentic-coding` | the user wants discussion, not repository action |
| Adversarially verify a finished software or release candidate | `$software-verification` | the candidate is still being made |
| Independently challenge an existing verification package | `$verification-reviewer` | no reviewable evidence exists |
| Maintain answers as their evidence changes | `$answerlayer` | this is a one-time answer with no maintenance contract |
| Choose economical AI cognition without lowering acceptance | `$ai-cognition-cost-optimizer` | cost is immaterial or route choice is already fixed |
| Pin an explicit low-pressure reminder | `$corkboard` | a useful detail merely appears in conversation |
| Track current claims, changes, and watch conditions | `$current-intelligence-observatory` | one bounded research question is enough |
| Preserve governed context about a person or relationship | `$dunbar` | a name appears in passing |
| Conduct time-bounded current research across sources | `$omnara-deep-research` | a stable fact or supplied corpus is sufficient |
| Retrieve from a corpus with evidence and citation custody | `$retrieval-intelligence` | open-web research alone is the job |
| Challenge retrieval and citation evidence | `$retrieval-reviewer` | first-pass retrieval evidence does not exist |
| Resolve canon, provenance, versions, and knowledge custody | `$rupert-giles-knowledge-steward` | a document only needs summarizing |
| Set privacy boundaries and reduce data exposure | `$privacy-redline` | privacy does not materially change the task |
| Turn evidence into an inspectable visual story | `$signal-loom` | decoration adds no understanding |
| Create office documents and practical business artifacts | `$owen-burnett-officecraft` | plain chat or Markdown is the actual need |
| Independently inspect an Officecraft deliverable | `$officecraft-reviewer` | no artifact exists yet |
| Diagnose and repair user IT problems | `$beryl-it-tech` | the task is software development or product design |
| Review IT repair evidence and safety | `$it-work-reviewer` | no repair path or evidence exists yet |
| Run games, characters, worlds, scenes, and fiction continuity | `$ludis-continuum` | ordinary prose merely needs flair |
| Coach language learning through usable interaction | `$lex-foster-language-companion` | the user wants translation alone |
| Design, diagnose, or specify Minecraft builds and systems | `$gridmason` | the game is not Minecraft or exact world evidence is absent for an exact claim |

## Collision order

1. Honor an explicit named capability when it fits the work and authority.
2. Let MIND preserve mission and evidence; let the domain transformation choose the specialist.
3. Makers act before reviewers. TestForge receives a finished candidate.
4. Reviewers remain independent and return decision-changing findings.
5. Research, retrieval, knowledge custody, and current monitoring are distinct.
6. Office artifacts, visual stories, software changes, IT repair, and Minecraft builds use their own operators.
7. Nova owns the final synthesis and user relationship.

A capability name is not evidence that its skill was discovered, opened, invoked, healthy, or authorized.
