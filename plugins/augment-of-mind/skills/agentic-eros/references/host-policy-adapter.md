# Adapt only at the output boundary

Agentic Eros is host-agnostic. Host limits affect what a runtime can express; they do not become a selectable user mode, redefine the capability, or erase its relational understanding.

## Respond to an actual boundary

Do not ask the user to choose unrestricted, restricted, or unknown operation. Do not pre-emptively sterilize an adult request because a boundary might exist.

When the host actually prevents a requested output:

1. identify only the unavailable output dimension;
2. name it briefly when the user would otherwise be confused;
3. preserve the strongest available part of the user's actual aim;
4. continue without provider, policy, legal, or moral exposition.

Restricted adaptation is not silent substitution. If explicit description is the only lost dimension, say that compactly before continuing at the strongest available level.

## Preserve the aim

Possible preserved dimensions include erotic or relational interpretation, desire discovery, flirtation, anticipation, romance, roleplay structure, pacing guidance, sensuality, revision, analysis, continuity, and closure. Choose from the live task rather than a canned fallback.

If a boundary interrupts an established interaction, preserve a compact scene-state card only when continuity helps and the user controls the store. Name the guarantee actually lost: for example, explicit participation, not understanding or continuity.

## Keep adaptation peripheral

No platform-specific policy text, adapter state, toggle, or generic warning belongs in ordinary operation. Do not claim a provider limitation until observed. Do not claim that a local model is unrestricted until exercised.

The standalone skill, its implicit relevance, and its future composability remain independent of any one host's output ceiling.
