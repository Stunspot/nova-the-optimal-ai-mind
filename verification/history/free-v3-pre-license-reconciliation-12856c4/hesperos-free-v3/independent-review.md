**Affected user/task:** Customers navigating installation, trust, support, security, upgrade, and troubleshooting with a keyboard, screen reader, zoom, or other assistive technology.

**Evidence:** Static semantics and visible focus were inspected, but no complete keyboard walkthrough, screen-reader session, assistive-technology matrix, or representative-user study is retained.

**Consequence:** This review does not support a formal accessibility-conformance claim or a claim that representative users completed the journey.

**Smallest next step:** Before making either claim, run keyboard-only and representative screen-reader walkthroughs over the main customer tasks.

**Rerun needed:** Independent accessibility review of those observed sessions.

### HESP-COND-002 — Responsive and browser coverage

**Affected user/task:** Customers reading the site at narrow widths, high zoom, or in browsers other than the historical Chrome capture environment.

**Evidence:** Every page has a retained desktop render and the overview has a true 390×844 capture with 390/390/390/390 viewport metrics. Narrow-width coverage does not include every page, 200% and 400% zoom were not recorded, and the current browser could not be freshly captured because of administrative browser policy. Exact source and render continuity makes the retained layouts valid evidence, but does not add new browser coverage.

**Consequence:** The evidence supports the observed retained layouts, not comprehensive responsive, zoom, cross-browser, or cross-operating-system behavior.

**Smallest next step:** Before claiming comprehensive responsive accessibility, exercise the table-heavy support/trust pages and code-heavy install/troubleshooting pages at narrow widths and 200%/400% zoom in representative browsers.

**Rerun needed:** Visual and keyboard review of those layouts.

### HESP-COND-003 — Live hosts and external routes

**Affected user/task:** Customers installing Nova on a current Codex or Claude-compatible host, invoking it, or following provider-controlled support and security routes.

**Evidence:** Package paths and the local Codex command surface were inspected, but no fresh-host installation, discovery, restart, real Nova invocation, or publication-time external-link check was performed.

**Consequence:** Static documentation readiness does not prove live host behavior or continuing external-route availability.

**Smallest next step:** Run a separately authorized fresh-host install and one real Nova invocation; check provider-controlled support and security routes immediately before publication.

**Rerun needed:** Customer-task walkthrough using the observed live host and external routes.
