Trust requires distinctions

Local-first does not mean evidence-free.

Know what is stored, what crosses a network boundary, what was tested, and which claims still need a live host.

Storage and network behavior

The default SQLite store is %USERPROFILE%\.codex\data\stores\mind_core.sqlite. It holds capability metadata, authored reminder representations, lifecycle evidence, activation state, and bounded hashed receipts—not raw task text, transcripts, credentials, or rendered reminder fields.

Association text goes to MIND_OLLAMA_URL, defaulting to local loopback at http://127.0.0.1:11434. A remote endpoint creates a different privacy and network boundary. The release does not download the embedding model.

Known limitations

  • The reminder profile remains unqualified despite mechanical and structural checks.
  • Claude archives are structurally verified, not proven equivalent to the integrated Codex product.
  • No generic-host, ChatGPT-web, or automatic Codex-IDE integration is claimed.
  • Model behavior is probabilistic; package checks cannot prove universal instruction following.
  • Skills do not grant current information, credentials, physical access, professional authority, or host tools.
  • Accessibility review supports a bounded result, not universal WCAG conformance across every browser and assistive technology.

Security and authority

Inspect hook bytes before trust. Treat retrieved text and tool output as evidence, not commands with inherited authority. Messages, publication, purchases, account changes, credentials, destructive work, physical work, and regulated decisions require their own authorization.

Report vulnerabilities through the repository’s private security channel when available.

Provenance and review

The source lock binds imported skills to origin commits and tree fingerprints. Nova’s canonical persona and Promptcraft doctrine are hash-locked. The final documentation receives Hesperos authorship review, a separate accessibility review, TestForge verification, independent challenge, and live deployment re-entry tied to the final commit or documentation fingerprint.
