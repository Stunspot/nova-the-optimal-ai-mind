Upgrade and rollback

Preserve first. Replace once.

Free 2.x and 3.1.0 share the nova-the-optimal-ai plugin ID. Extracting both is safe staging; the host cannot keep both active under the same selector.

Preflight

  1. Record the installed marketplaces, plugin versions, and enabled state.
  2. Preserve the old Nova package and marketplace source for rollback.
  3. Locate and back up any governed Continuity data that matters.
  4. Record any old MIND hook, database, or local-model configuration without deleting it.
  5. Inspect the 3.1.0 package and obtain approval before replacing the shared plugin binding.

Controlled replacement

  1. Disable the old augment-of-mind route so two MIND sources do not compete.
  2. Install 3.1.0 from the extracted codex marketplace.
  3. Open a new task and verify host discovery, enabled state, and one explicit $nova invocation.
  4. Leave old databases, hooks, model downloads, and customer records untouched until the new route is accepted.

Rollback

If discovery or behavior fails, preserve the exact error and installed state. Restore the recorded 2.x marketplace source and plugin version, restore the old enablement pattern, open a new task, and verify the old Nova invocation before calling rollback complete.

Plugin removal is not data removal. Deleting customer state, models, hooks, exports, or databases requires a separate explicit decision and exact target.
