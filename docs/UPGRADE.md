# Upgrade to Free 4.3.0

Free 4.3.0 preserves the single Nova front door and 28 installed skills. Companion presentation reflects current owner dispositions: Project Bridge, OMNARA, Beryl, and Knowledge Desk are presented; the Intelligence Observatory, Oracle Reading, AnswerLayer, and Giles standalone apps are not. Their in-chat skills remain installed.

Back up any owner-managed work before replacing the package. This edition does not scan unrelated folders, import data, or remove skill files. Continue using each owner’s canonical store and ask Nova to prepare or change work in conversation.

This source candidate is prepared for qualification. Installation, host discovery, and behavior must be verified on the target host.

## Keep existing app work

Back up the work location shown by each app. OMNARA keeps its campaign vault; Beryl and the other active companions retain their owner-managed data outside installation. Older native records remain usable through their retained advanced viewer or native import. No update scans unrelated folders or converts records automatically. If an app opens empty, choose your existing folder before creating a new store.

## Apply the chosen complete edition

Record the currently installed version, marketplace source, enabled state and configured estate root. Keep the previous complete package and configuration for rollback, and back up important owner records separately.

Extract the new complete package to a stable staging location. Inspect the chosen host route, then have the installing agent apply it through the live host's supported plugin installation or refresh mechanism. For Codex, the local marketplace must point to this edition's `codex` folder; use the [installation route](../START-HERE.md#manual-codex-recovery). Marketplace `upgrade` refreshes Git snapshots, not a local ZIP. If an actual competing installation requires a choice, resolve it within existing authority or obtain that choice before replacement.

Preserve the operation result. Restart the host, open a new conversation and verify the intended installed 4.3.0 version and enabled state. Ask Nova for one small real result and read-only status of the existing estate if configured. If the old version is still installed, return to the supported installation/refresh surface with that diagnostic. Do not delete a cache or service store to force the result.

Confirm a known project, catalog route or retained item still resolves through its owner. An empty default path does not establish lost data. No update step should silently import, merge, move, migrate or delete records.

## Roll back without erasing work

Apply the preserved previous complete package through the same live host installation surface. Keep the same estate registry unless a separately authorized reversible migration is required. Restart, open a new conversation and verify the intended prior installed version, discovery and read-only status. Restoring downloaded files alone is not an observed rollback.

Plugin removal and data removal remain separate decisions. Preserve records and prior packages until recovery is settled. The historical notes that follow describe earlier product changes and artifact compatibility, not additional current setup requirements.

Free 3.8.0 carries the repaired Trellis runtime and keeps MIND at 0.4.0, but Trellis 1.1.0 accepts only `cd-model-agnosticism-model-set/v2` and `cd-model-agnosticism-observation-sequence/v2` inputs and emits only v2 receipts.

There is no automatic v1-to-v2 Trellis migration. Preserve every v1 input and receipt byte-for-byte as historical evidence; structural recognition by the v2 receipt schema does not rerun, endorse, or upgrade the old calculation. To run the current engine, construct a new v2 model set and observation sequence with explicit epistemic lane, candidate-selection and stopping contracts, structured step semantics, parameter provenance, and the current comparison and calibration bindings. Do not relabel a v1 document or rewrite a historical receipt. When the original inputs or a defensible v2 mapping cannot be recovered, retain the history and return to qualitative Model Agnosticism rather than manufacturing a current result.
