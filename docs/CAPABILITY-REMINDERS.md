# Understand MIND capability reminders

Arm's Reach keeps relevant capabilities semantically near the live task. It does not rank the estate or decide for Nova.

## The two delivery moments

### Before the model turn

The Codex `UserPromptSubmit` hook examines explicit identity-shaped cues such as `$gridmason`. If the active Core estate is available, it prepares a bounded reminder field. For a general prompt, the hook requests contextual association rather than pretending raw text contains the task's full meaning.

Codex requires the user to review and trust the exact hook bytes through `/hooks`. Package presence does not establish trust or delivery.

### After Nova understands the task

Nova derives a semantic membrane from the intended transformation, situation, distinctive cues, example, and negative boundary. The local association service compares that membrane with six views per capability and returns the complete radius neighborhood plus explicit one-hop relations.

Nova opens only the handles whose transformations materially fit.

Capability Promotion gives the reminder layer memory of its own maintenance. Language such as “add this skill,” “install this plugin,” or “we should add a program that lets you…” brings forward the need to include that durable capability in MIND's reminder cards and embeddings. The user never needs to name or remember the promotion layer.

## Read the evidence states correctly

| State | What it establishes |
|---|---|
| Skill folder exists | package presence |
| Plugin installed and enabled | host configuration |
| Fresh task exposes a handle | discovery |
| Hook trusted | host accepted those exact hook bytes |
| Hook returned `additionalContext` | the hook prepared and emitted a field |
| Provider receipt | the host reports context delivery |
| Model uses a capability | behavior in that turn |
| Repeated discriminating probes pass | bounded behavioral consistency |

None of these silently proves the next.

## The shipped profile

The Free Nova estate contains 41 public-safe capability cards, 246 semantic views, 33 explicit relations, and 1024-dimensional vectors generated with local `qwen3-embedding:0.6b`.

An isolated Core activation passed SQLite integrity and foreign-key checks. Radius tuning produced these representative fields at `0.33`:

- Minecraft build planning: Gridmason plus Measurement Intelligence;
- prompt authoring: Promptcraft plus Nova, MIND integration, and Kairos;
- finished installer verification: Agentic Coding plus the TestForge operator and reviewer.

The focused [Capability Promotion probe receipt](../verification/capability-promotion-probes.json) records the exact “add skill,” “add program,” “install plugin,” and unrelated-control results.

Those smoke probes informed the current geometry. The profile remains `unqualified` pending the larger discriminating and fresh-host suite.

## Privacy

The public estate contains authored metadata, not private skill bodies, credentials, user prompts, personal records, or Collaborative Dynamics' private capability inventory. Query sessions store hashes and bounded receipts rather than raw task text. See [Privacy and trust](PRIVACY-AND-TRUST.md).

## Degraded behavior

If the database, active snapshot, local embedding service, MCP server, or trusted hook is unavailable, MIND must name the exact lost guarantee and continue only from capabilities the host actually exposes. Folder browsing is not a substitute for semantic association.

The re-entry condition is the repaired missing boundary: trusted hook, active database, compatible Python runtime, available MCP server, or restored embedding provider.
