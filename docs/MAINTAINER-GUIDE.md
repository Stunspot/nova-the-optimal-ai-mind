# Maintainer guide

This is a source-repository maintainer reference. The extracted customer package carries it for transparency but does not include a buildable source checkout.

The source of the distributable plugin is plugins/nova-the-optimal-ai. Its LOADOUT-MANIFEST.json must name exactly the twenty-five sibling roots. MIND's sixteen Faculty Cores remain nested beneath skills/nova/references/mind/faculty-cores.

Import maintained source through an explicit runtime selection, record its repository commit and selected-tree digest in design/source-lock.json, then name every edition overlay. Generated Nova Emergent package trees are comparison evidence, not canonical sources.

Build deterministically with tools/build_release.py and verify the extracted package with tools/verify_package.py. Use the system skill and plugin validators, run the focused repository tests, then conduct independent Hesperos and TestForge cycles. Do not convert static package evidence into fresh-host or publication claims.

Do not invoke private-repository GitHub-hosted Actions until current account capacity has been read and authorized under the repository operating boundary. Local evidence is not hosted-execution evidence.

Never publish an intermediate candidate. Resolve every component-license gate recorded in THIRD-PARTY-NOTICES.md, reconcile conflicting component metadata, clean tracked source, freeze the source lock, and obtain separate authority for tag, push, release, directory submission, or public announcement.
